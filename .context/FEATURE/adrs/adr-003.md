# ADR-003: Block Agents Without Configured Tools

## Status

Accepted

## Date

2026-05-19

## Context

After removing role-based runtime fallback, an agent can have no rows in `ai_agent_tools`. The system needs explicit behavior for that state.

## Decision

Block runs for agents without configured tools. Treat the missing assignment as a configuration error and expose/log the reason as `agent_tools_not_configured`.

## Alternatives Considered

### Alternative 1: Execute without tools

- **Description**: Let the LLM respond without function calling.
- **Pros**: More tolerant runtime behavior.
- **Cons**: Can silently degrade automation behavior and hide setup problems.
- **Why rejected**: Missing tool permissions should be visible.

### Alternative 2: Apply default preset at runtime

- **Description**: If no tools are configured, infer tools from role/type.
- **Pros**: Avoids blocked runs.
- **Cons**: Reintroduces implicit permissions and two sources of truth.
- **Why rejected**: It conflicts with persisted permissions as source of truth.

## Consequences

### Positive

- Misconfigured agents fail explicitly.
- Operators can audit and fix the missing setup.

### Negative

- Deployments must backfill existing agents correctly.
- Newly created agents need explicit tool setup before execution.

### Risks

- Existing tenants may see blocked runs if migration misses tools.
- Mitigation: add migration coverage and clear structured logs.

## Implementation Notes

Run hydration and tool execution should use a clear blocked/failure state rather than returning an empty implicit tool list.
