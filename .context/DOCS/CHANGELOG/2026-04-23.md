- [HH:MM] PERF [ai/autopilot]: QW1 — Publica snapshots hidratados em `ai.run.request` (elimina 2-3 round-trips HTTP gateway→API por run)
    - Causa: gateway buscava prompt/context/tools via HTTP (`/internal/ai/prompt|context|tools`) a cada run mesmo quando o publisher (Laravel) já tinha tudo em memória/cache. Latência adicional ~100–300ms por run.
    - Mudança: criado `AutopilotRunSnapshotResolver` que hidrata `prompt`, `context` (`{ticket_id, tenant_id, status, subject}`) e `tools` (definitions OpenAI) e injeta no payload do XADD com `hydrated_at` ISO8601. Falha individual em qualquer slice retorna `null` → gateway faz fallback HTTP normal (backward compatible). Gateway já consumia esses campos via `getPromptSnapshot/getContextSnapshot/getToolsSnapshot` com gate de frescor de 90s (`isRecent`).
    - Cache: contexto cacheado por 300s em `autopilot:snapshot:context:{ticketId}` para reaproveitar entre runs do mesmo ticket. Prompt e tools já têm cache próprio nos services existentes.
    - Arquivos:
        - `api/src/Domain/Ai/Services/AutopilotRunSnapshotResolver.php` (novo)
        - `api/src/Domain/Ai/Jobs/DispatchAutopilotRunJob.php` (alterado: import + DI no `handle()` + injeção de snapshot no `$streamPayload` antes do publish)
    - Validacao: `get_errors` limpo nos dois arquivos. `pest tests/Feature/DispatchAutopilotRunJobTest.php tests/Feature/AutopilotRunDispatcherListenerTest.php tests/Feature/Ai/AutopilotRoutesAuthTest.php` → 18 passaram, 3 falharam por DB de teste ausente (`agentflix_test`), não relacionados.
    - Pendente: medir em prod (1) latência p50/p95 do consumer no gateway antes/depois; (2) volume de chamadas a `/internal/ai/{prompt,context,tools}` (deve cair drasticamente).
    - Ref: PERF-AUTOPILOT-QW1
