- Webchat público: evitar parsing manual legado de `window.location.pathname` para tenant; priorizar `ActivatedRoute` e repasse explícito de `tenantId` para componentes filhos.
- Webchat arquivo/imagem: `af-chat-bubble` não renderizava mídia — só texto. Fix: (1) adicionar inputs `type/fileUrl/mimeType` ao bubble, (2) incluir `fileUrl`+`mimeType` na mensagem otimista do `sendFileMessage`, (3) passar dados no template do `chat-window`. Mensagens vindas do atendente chegam via `webchat:agent_message` com `...msgData` — já incluem fileUrl se o gateway enviar.
- Em correções de integração frontend-backend, validar contrato real do endpoint (campos `tenant_id`, `visitor_name`, `visitor_phone`) antes de manter headers legados (`X-Tenant-Slug`).
- Para websocket entre serviços, sempre validar compatibilidade JWT em 2 eixos: segredo de assinatura compartilhado e claims obrigatórias do gateway (`sub` + `tenant_id`).
- Gateway logs: evitar forçar logger JSON estruturado no dev por padrão; manter modo colorido local e usar flag (`LOG_STRUCTURED`) para JSON em produção/observabilidade.
- Delegação entre agentes: mismatch de contrato pode impedir roteamento por nome. O serviço aceita nome/UUID (`api/src/Domain/Ai/Services/AiAgentDelegationService.php`, resolve por `LOWER(name)`), mas o endpoint interno exige `target_agent_id` como UUID (`api/src/Domain/Ai/Http/Controllers/InternalAiController.php`, validação `uuid`). Se o fluxo do gateway enviar nome, a delegação falha com 422 e aparenta "não trocar de agente".
- BUG AUTOPILOT WEBCHAT (2026-04-22): (1) IA para após 2-3 msgs porque `AiGateKeeperListener` não propaga `session_id` do `event->context` para o contexto do `AutopilotTriggerFired` → `DispatchAutopilotRunJob` não inclui `session_id` no `input_context` do run → Gateway recebe run sem `session_id` → após 1a resposta (que funciona porque o send_message tool usa SendChatMessageAction que consulta ChatSession via ticket_id), nas mensagens subsequentes o fallback HTTP pode falhar silenciosamente. (2) Desincronização painel interno: `SendChatMessageAction::create()` com `source='ai'` não emite `emitNewMessageEvent` (comentário linha 121-122 explica), então o agente interno não vê a mensagem da IA. O painel mostra "Iniciar atendimento" porque o ticket permanece em status `pending` sem `started_at`. Fix: (1) propagar `session_id` em `AiGateKeeperListener`; (2) emitir `emitNewMessageEvent` também para mensagens `source='ai'` outgoing em tickets webchat.
- Gateway autopilot/webchat: respostas podem vazar como JSON literal `{"name":"send_message","arguments":...}` quando o payload de tool-call não é normalizado. Regra: tratar na borda do gateway (parser aceita array/objeto e finalização extrai `arguments.content` antes do envio implícito).
